# Firecrawl / Alexandria 利用評価

更新日: 2026-09-30 JST

## 目的
わらしべAI Research LAB の技術調査・API/SDK仕様確認・GitHub Issue/PR・研究論文探索で、Firecrawl / Alexandria を通常のWeb調査と比較し、採用価値を小規模に評価する。

## 現在の扱い
- ChatGPT側では Firecrawl プラグインが利用可能。
- Alexandria は Firecrawl 経由の構造化データ探索候補として扱う。
- 本体コードの必須依存にはしない。
- Firecrawl / Alexandria の結果だけで実市場データ、成約事実、実取引許可、MAIN変更を確定しない。

## 初期評価対象
まず開発・研究用途のみで比較する。

1. Python/API/SDK の最新仕様確認
2. GitHub Issue / merged PR / README / 開発ドキュメント探索
3. AIエージェント、MCP、ガードレール等の論文探索
4. 既存実装・成熟OSS・公式SDKの再利用候補探索

商品価格・実成約データなど商取引判断への利用は、上記の評価後に別マイルストーンで検討する。

## 比較項目
同じ問いを通常Web調査と Firecrawl / Alexandria で調べ、次を記録する。

- 一次資料・公式資料への到達率
- 情報の鮮度
- URL・出典の追跡可能性
- 同じ問いでの再現性
- 調査時間
- 利用コスト / クレジット消費
- ノイズや重複の少なさ
- わらしべAIの開発判断への有用性

メール等に記載されたベンダー内部評価値は参考情報とし、採用判断の根拠にはしない。

## 安全条件
- 読み取り・検索・抽出を優先する。
- browser interaction、フォーム送信、外部書き込み等の副作用を伴う操作は、この評価の対象外。
- Secrets、実DB、実取引、決済、MAIN/production 変更を行わない。
- 重要な仕様は公式一次資料または独立した根拠で再確認する。
- プラグインが利用不能でも権限拡張や危険な迂回をせず、通常Web調査へフォールバックする。

## 採用判定
最低3件の異なる開発調査で比較し、Firecrawl / Alexandria が次のいずれかを安定して改善した場合に、Research LAB の標準調査候補へ昇格する。

- 一次資料への到達
- 調査時間
- 再現性
- ノイズ削減
- 開発判断に必要な根拠の明確さ

昇格後も、単独ソースを真実扱いしない。

## 次の一件
現在進行中の実取引監視ゲートのオフライン検証を優先しつつ、次の開発調査テーマ1件で通常WebとFirecrawl/Alexandriaの比較結果を記録する。


## 比較試験 1: Python urllib のリダイレクト抑止

### 問い
Python 標準ライブラリ `urllib.request` で、許可済みホストから別宛先への HTTP リダイレクトを自動追跡しない実装方針を確認する。

### 通常Web調査
- Python公式ドキュメントの `HTTPRedirectHandler.redirect_request` に到達。
- リダイレクト時に `Request` または `None` を返す契約と、必要に応じて `HTTPError` を送出する説明を確認。
- GitHub上のセキュリティ議論も見つかり、許可先検証後のリダイレクトが別ホスト到達につながり得る設計上の注意を確認。
- 一次資料への到達は良好。検索結果はドキュメント中心で、実装例の探索は追加検索が必要。

### Firecrawl / Alexandria系の開発者検索
- 同じ問いで Python公式ドキュメントを上位結果として取得。
- さらにGitHubの実装・PR文脈として、`HTTPRedirectHandler` を利用してリダイレクトを拒否し、301/302/303/307/308を実HTTPサーバーで検証した事例を同一検索内で取得。
- 公式仕様と実装事例を一度に並べられ、Research LABの「仕様確認 + 既存実装探索」に有用。
- 検索結果にはStack Overflowや古い文書も混在するため、一次資料優先の再確認は引き続き必要。

### 暫定比較
| 項目 | 通常Web | Firecrawl / Alexandria系 |
| --- | --- | --- |
| 公式一次資料への到達 | 良好 | 良好 |
| GitHub実装・PR文脈 | 追加検索が必要 | 同一検索で複数取得 |
| ノイズ | 比較的少ない | やや混在 |
| 開発判断への有用性 | 高い | 高い。実装例探索で優位 |
| 再現性 | URL/検索語で追跡可能 | 検索語と結果ID/URLで追跡可能 |

### コスト観測
- 比較実行後のFirecrawlチーム残クレジット表示は `1001`、プラン表示は `1000`。追加付与等で残量がプラン値を上回る場合があるため、この1回の検索コストをこの残量だけから逆算しない。
- 今回は検索前残量を固定記録していないため、1試行あたりの正確な消費量は未測定。次回以降は前後差分を記録する。

### 判定
1件目では、通常WebとFirecrawlの両方が公式仕様へ到達した。Firecrawl側は同じ検索でGitHubの実装・PR文脈も集約でき、既存実装探索では有用性が高かった。まだ1/3件なので標準調査ルートへの昇格は行わない。



## 比較試験 2: GitHub Actions のSHA固定と再現可能性

### 問い
GitHub Actionsで、移動するブランチ参照ではなく実行対象のコミットSHAを固定してチェックアウト・依存Action参照することが、再現性と安全性にどう寄与するかを確認する。

### 通常Web調査
- GitHub公式の Secure use reference に到達し、第三者Actionは完全長コミットSHAへ固定することが、不変な参照としての推奨であることを確認。
- GitHub公式の workflow / event ドキュメントから、各実行には関連するコミットSHAとrefがあり、runnerには `GITHUB_SHA` / `GITHUB_REF` が設定されることを確認。
- 公式一次資料への到達は良好。GitHub自身の説明として根拠を得やすい。
- 個別OSSで「branch refからhead SHAへ変更した理由」まで追うには追加検索が必要。

### Firecrawl / Alexandria系の開発者検索
- GitHub Docsを参照する実装ガイドに加え、複数の公開リポジトリのCI運用文書と、実際にmutable branch refからhead SHAへ変更したPR文脈を同一検索で取得。
- PR文脈では、label/comment等の時点とrunner開始時の間にbranchが更新されるTOCTOUリスクを避けるため、トリガー時SHAへ固定する具体例を確認。
- 公式仕様だけでなく「なぜ現場で変更されたか」まで一度に取得でき、Research LABの既存 `github.sha` 固定方針の妥当性確認に有用。
- 一方で、検索結果は第三者リポジトリのポリシー文書やPRも多く、一般化前にGitHub公式一次資料との照合が必要。

### 暫定比較
| 項目 | 通常Web | Firecrawl / Alexandria系 |
| --- | --- | --- |
| GitHub公式一次資料への到達 | 良好 | 間接参照を含め良好 |
| 実際のIssue/PR・運用例 | 追加検索が必要 | 同一検索で複数取得 |
| 設計理由の把握 | 公式原則が明確 | 原則 + 実装変更理由まで把握しやすい |
| ノイズ | 少ない | やや多い |
| Research LABへの有用性 | 高い | 高い。既存実装の背景確認で優位 |

### コスト観測
- Firecrawl検索前の残クレジット表示: `1000`。
- 同一比較内の開発者検索後の残クレジット表示: `998`。
- 観測差は `-2`。この区間では本比較用のFirecrawl開発者検索を1回実行したが、チーム単位残量のため他の同時利用があれば混入し得る。したがって「この検索は必ず2クレジット」と一般化しない。

### 判定
2件目でも、通常Webは公式一次資料確認に強く、Firecrawl側はGitHubの具体的なIssue/PR/運用文脈を同時に集約する点で有用だった。1件目と同様、仕様確定は公式資料を優先し、Firecrawl/Alexandriaは既存実装探索・背景調査の加速用途に向く。まだ2/3件なので標準調査ルートへの昇格は保留する。


## 比較試験 3: AIエージェント実行ガードレール論文探索

### 問い
AIコーディングエージェントやツール実行型エージェントに対する、実行前・実行中のガードレール研究を2026年の公開論文から探索し、わらしべAIの自動研究・自己修復設計に使える一次資料へ到達できるか比較する。

### 通常Web調査
- arXivの `AgentGuard: Learning Execution Guardrails from Anomalous Coding-Agent Trajectories` に到達。
- 実行履歴中の異常パターンから、命令レベルの制約を学習して必要時だけ適用する設計を確認。
- 2026年公開の関連論文として、エージェント安全性、実行境界、tool-use guardrailの候補も複数得られた。
- 一次資料へ直接到達しやすい一方、関連研究を広く並べるには複数検索が必要。

### Firecrawl / Alexandria系のResearch Index
- 同じテーマで `AgentGuard` を最上位に取得。
- 同時に、`StepGuard`、`AgentTrust`、`TraceSafe`、`DreamGuard`、`No Certificate, No Execution` 等、実行前監視・runtime interception・trace certification・長期軌跡評価に関する2026年論文をまとまって取得。
- 各結果にpaper ID、arXiv ID、タイトル、abstract、rank scoreが付いており、関連研究の比較表を作りやすい。
- 一方で、abstract検索結果だけで手法や数値の妥当性を確定せず、採用判断時には原論文本文・実装・追加資料を確認する必要がある。

### わらしべAIへの示唆
- `AgentGuard`: 過去の異常実行から条件付きルールを学ぶ考え方は、Libraryの問題管理ログから再発防止ルール候補を生成する設計と相性がよい。
- `StepGuard` / `AgentTrust`: 実行前にtool actionを監査し、allow / warn / block / review等の判定を挟む考え方は、現在のPolicy Guardと実取引監視ゲートの拡張候補。
- `No Certificate, No Execution`: 生成された提案と実行許可を分離し、チェック可能な証明・承認がなければ実行しない考え方は、既存のHuman Gate / `external_action_authorized=False` 方針と整合する。
- これらは研究上の候補であり、そのまま本番採用・実取引許可を意味しない。

### 暫定比較
| 項目 | 通常Web | Firecrawl / Alexandria系 |
| --- | --- | --- |
| arXiv一次資料への到達 | 良好 | 良好 |
| 関連研究の横断探索 | 複数検索が必要 | 1回で複数の高関連論文を取得 |
| メタデータの構造化 | ページごとに確認 | paper/arXiv ID・abstract・scoreが揃う |
| ノイズ | 比較的少ない | 今回は高関連結果が多い |
| Research LABへの有用性 | 高い | 高い。研究テーマの棚卸しで優位 |

### コスト観測
- Firecrawl Research Index実行前の残クレジット表示: `997`。
- 実行後の残クレジット表示: `997`。
- この観測では差分 `0`。ツール種別、キャッシュ、課金タイミング等の影響があり得るため、Research Indexが常に0クレジットとは判断しない。

### 3件評価のまとめ
3件の比較では、通常Web調査は公式一次資料の確定確認に安定して強かった。一方、Firecrawl / Alexandria系は、開発者検索ではIssue/PR/実装背景、Research Indexでは関連論文群を構造化して横断収集する用途で一貫して追加価値があった。

**Research LABではFirecrawl / Alexandriaを標準調査候補へ昇格する。** ただし役割は「探索・候補収集・横断比較の加速」とし、重要仕様・安全条件・実取引判断は公式一次資料または独立した根拠で再確認する。利用不能時は通常Webへfail-safeにフォールバックし、権限拡張や迂回をしない。
